# App 界面设计

## 设计目标

Build 26 是户外单手可用的纯蓝牙车辆工具。界面把连接、开关锁和物理结果放在第一优先级，车辆数据与诊断信息分页展示。不可靠功能没有操作入口，技术协议号不占据日常界面的主要层级。

## 视觉系统

- 主色取自 App 图标的深蓝，用于连接、关锁和主操作。
- 橙色用于开锁与需要注意的状态，绿色用于连接就绪和已验证边界。
- 页面使用浅色蓝色渐变背景、系统材质卡片和统一圆角，深色模式交给系统动态颜色处理。
- 连接、锁态和风险状态同时使用图标、文字和颜色，不仅依赖颜色。
- 所有文字使用系统字体与 Dynamic Type，所有图标使用 SF Symbols，不引入网络图片或第三方 UI 依赖。

## 三页结构

### 钥匙

1. 首屏主卡展示 BLE 阶段、操作消息、信号、锁态和最近回读时间。
2. 连接按钮在未连接时占满宽度，已连接时切换为刷新和断开。
3. 开锁和关锁使用两个大按钮，必须长按 1.2 秒。按住期间显示线性进度，并尊重减少动态效果的系统设置。
4. 结果卡区分发送中、回包与回读一致、设备拒绝和结果未知。
5. 物理确认卡固定展示两条关锁标准：仪表熄灭代表车辆断电，轮毂锁必须真实锁住。
6. 密钥页显示 8 字节长度反馈，并明确密钥只保存在 iPhone Keychain。

### 状态

1. 页首使用统一连接横幅，让用户不离开当前页也能看到连接和锁态。
2. 电量、速度、骑行模式、本次里程、剩余里程和锁电压使用双列指标卡，避免三列布局在小屏幕上拥挤。
3. 锁态、固件版本和最近回读时间与主指标分层展示。
4. 页底用普通语言说明当前可用与已停用的功能，不把协议号当作主界面文案。

### 记录

1. 旧骑行数据卡区分无记录、设备有记录和已读取三种状态。
2. 数据读取后用分组行展示时间、时长和用户 ID，用户可以先保存，再二次确认清除。
3. 外部锁只显示精简的停用说明，不展示查询或控制按钮。
4. 脱敏诊断默认折叠，空状态、事件列表和分享入口使用同一卡片。

## 安全与可访问性不变量

- 未连接、锁态未知或已有操作进行时，所有协议按钮不可用。
- App 不显示“开锁成功”或“关锁成功”，只描述设备回包和协议状态回读是否一致。
- 长按进度只改善反馈，不改变 1.2 秒门禁、幂等检查或单次发送逻辑。
- 布局支持 Dynamic Type，按钮、状态和诊断内容包含明确的无障碍标签或可合并文本。

## 明确不进入当前界面

远程状态、地图、轨迹、告警、云端记录和服务设置不进入 Build 26。`0x61`、`0x62`、`0x81` 以及系统信息、日志、RFID、电源、服务器、APN 和 OTA 都不提供隐藏入口。
