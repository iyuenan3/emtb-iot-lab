# IoT 蓝牙现场调试工具

这是一个仅供个人调试使用的原生 iPhone App。它既能通过兼容协议现场连接指定的自行车 IoT 设备，也包含单车远程控制入口。本项目为非官方独立实现，与设备制造商无关联。

## 运行环境

- iPhone 17，iOS 26.6
- 安装了 Xcode 26.6 的 Mac
- 必须使用真机，iOS 模拟器无法连接真实 CoreBluetooth 设备

## 安装方法

1. 使用 Xcode 打开 `IoTBluetooth.xcodeproj`。
2. 选择 `IoTBluetooth` Target，在 Signing & Capabilities 中选择自己的 Apple ID 开发团队。
3. 使用数据线或无线调试连接并信任 iPhone，然后将它选为运行设备。
4. 点击 Xcode 的 Run 按钮安装并启动 App。
5. 首次启动后，在“更多 > 密钥与日志”输入 8 字节设备密钥。密钥只保存在 iOS Keychain 中。设备密钥轮换后，在同一输入框中粘贴新密钥并点击“更新设备密钥”，旧值会被直接覆盖。
6. 只有修改系统配置或执行 OTA 时，才需要另外输入 4 字节维护密钥。

BLE 现场功能不依赖网络。现场日志和设备快照保存在 App 的 Documents 目录，可以通过 iOS 分享菜单导出。远程功能需要通过 HTTPS 连接 `iot-remote` 服务。

## Mac 本地调试密钥

工作区根目录的 `.env.local` 可以保存 `BLE_KEY`，仅供 Mac 命令行 BLE 探针使用。该文件被根级 Git 忽略，权限必须保持为 `600`。工具只能按 dotenv 规则读取指定字段，不能用 shell `source`，也不能打印密钥值。

iPhone App 运行时无法读取 Mac 上的 `.env.local`，当前仍从 iOS Keychain 读取设备密钥。若以后通过 Xcode 在构建阶段注入该变量，密钥会进入调试 App 包，只能用于个人测试，不能视为安全存储或发布方案。

将 `Secrets.xcconfig.example` 复制为被 Git 忽略的 `Secrets.xcconfig`，填写本机要调试的车辆编号、IMEI 和 BLE MAC。真实设备标识不进入仓库。

当前 App 使用“车辆、地图、记录、更多”四页结构。车辆页聚合日常状态和双通道控制，设备信息、密钥、调试控制与维护能力收纳在“更多”，避免户外误触。

## 已实现的蓝牙功能

- 固定设备识别、扫描、认证、自动重连和状态刷新
- 长按开锁与关锁，接收设备结果后自动回读锁状态
- 读取电量、骑行模式、锁状态、系统信息和未上传骑行数据
- 控制大灯、速度模式、油门、尾灯、滑板车电源、RFID 和外部锁
- 修改服务器与 APN、读取诊断日志、通过本地文件执行 OTA

## 安全说明

- 开锁和关锁必须长按 1.2 秒，自动重连不会重复执行控制命令。
- 开锁、关锁、速度档位、服务器和可判定的 APN 配置会先比较当前状态，相同操作直接返回，不重复写入。其余等待回包的操作均有超时回收，不会无限显示“正在操作”。
- iPhone App 的设备密钥和维护密钥不会写入源码、日志或导出文件。Mac 命令行调试使用的 `.env.local` 是本机明文文件，必须保持权限 `600`，不得提交或复制到服务器。
- 服务器修改、APN 修改、OTA 和旧数据清除均需要额外确认。
- TCP 协议定义了心跳和定位上报间隔，但已经验证的 BLE 接口没有提供这些字段。本工具不会发送未经验证的配置字段。
- OTA 前应确保设备电量充足，并让手机始终靠近设备。
