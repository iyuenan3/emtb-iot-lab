# 功能实现状态

当前 iPhone App 开发基线为 Build 23，目标是一个纯蓝牙、单连接单动作的最小车钥匙，并恢复早期 Build 2 已验证过的主锁读取与直接控制链。

## 已完成

| 范围 | 状态 |
| --- | --- |
| 单页界面 | 只显示手动连接、长按开锁、长按关锁、结果提示、密钥和本机诊断 |
| BLE 连接 | 只扫描配置的设备、发现 NUS 服务并使用 8 字节设备密钥认证 |
| 锁态读取 | 认证后读取一次 `0x31`；控制回包和必要回执后再次读取，用于幂等和一致性提示 |
| 控制协议 | 活跃命令白名单只有认证 `0x01`、开锁 `0x05`、错误 `0x10`、关锁 `0x15`、主锁读取 `0x31` |
| 单次动作 | 每次连接只能选择开锁或关锁一次，不能在同一连接反向操作 |
| 直接写入 | 认证通知一旦成功，控制入口不再依赖 `didWriteValueFor` 回调顺序；写入回调只记录成功或失败 |
| 结束策略 | 收到设备结果后立即发送同命令 `0x02` 必要回执，等待 0.8 秒回读主锁，再主动断开 |
| 失败策略 | 8 秒超时、写入失败或提前断连都标记为结果未知，不重连、不重试 |
| 本机安全 | 设备密钥保存在 iOS Keychain；按用户要求，开关锁和密钥变更不再调用 Face ID |
| 构建目标 | 远程控制、BLE 事件上传和维护页面已从 Xcode Target 移除 |
| 诊断 | 控制链事件保留在进程内，可从“诊断记录”分享脱敏文本 |
| 自动验证 | 生产会话状态机回调顺序测试、9 项源码守卫、无签名构建、签名构建和签名校验均通过 |
| 真机安装 | 已安装到配对 iPhone，并从设备读回版本 `1.0 (23)`；未启动 App，也未发送车辆控制指令 |

旧的远程服务和研究代码仍保留在仓库中，便于审计和恢复历史，但不进入 Build 23 App。此前部署的 `iot-remote` revision `469f154b75bb243e61cd1dd3f291fde0256bb7bb` 没有在本轮修改或重新部署。

## 当前现场问题

Build 21 和 Build 22 已确认能够完成设备认证，但控制按钮没有产生车辆动作。代码回溯定位到 Build 21 引入的 `pendingWrite` 门禁：认证通知可先到达并让界面显示就绪，控制按钮却仍等待写入完成回调清除此门禁。Build 23 删除这一回调顺序依赖，恢复 Build 2 和厂商原始实现使用的直接写入方式。此修复仍需真实车辆分别验收开锁和关锁。

## 明确取消的 App 功能

- 远程状态、地图、轨迹、告警、指令记录和服务设置
- 自动读取 `0x60` 骑行数据和 `0xFA` 系统信息
- 自动重连、自动刷新、自动状态同步和离线事件补报
- 车辆设置、RFID、外部锁、服务器、APN、日志读取、旧数据清理和 OTA
- 根据 BLE 回读宣称仪表、动力或轮毂锁已经到达物理结果

## 尚未完成

1. Build 23 只连接不控制时的锁态回读与稳定性验收。
2. 单次开锁后的协议回包、锁态回读、仪表、动力和轮毂锁验收。
3. 从全新连接执行单次关锁后的协议回包、锁态回读、仪表、动力和轮毂锁验收。

上述实车步骤需要用户在车辆旁人工确认。代码、测试、编译和安装都不能代替物理验收。
