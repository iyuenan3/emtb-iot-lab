# 功能实现状态

当前 iPhone App 开发基线为 Build 24，目标是纯蓝牙、常连接、完整覆盖 V1.2.5 文档正式 BLE 功能的现场工具。

## 已完成

| 范围 | 状态 |
| --- | --- |
| 三页界面 | 车钥匙、车辆设置、数据与外设，日常控制和高风险工具分开 |
| BLE 连接 | 手动扫描配置设备、发现 NUS 服务、使用 8 字节设备密钥认证 |
| 常连接会话 | 一个物理连接认证一次，操作完成后复用连接 Key，允许继续下一项操作 |
| 主锁 | `0x05` 开锁、`0x15` 关锁、必要回执、`0x31` 状态回读和幂等保护 |
| 车辆信息 | `0x60` 电量、模式、速度、本次里程和剩余里程解析与展示 |
| 基础设置 | `0x61` 前灯、模式、油门和尾灯，默认不修改，确认后发送 |
| 高级设置 | `0x62` 掉电保存、巡航、启动方式和三档限速，范围校验和高风险确认 |
| 旧骑行数据 | `0x51` 读取与单独分享，`0x52` 只在已读取后确认清除 |
| 外部锁 | `0x81` 电池锁、车轮锁、钢缆锁查询与控制，控制后状态查询 |
| 失败策略 | 写操作超时、写入失败、回读不一致或提前断连都标记未知并断开，不重连、不重试 |
| 本机安全 | 设备密钥保存在 iOS Keychain，连接 Key 仅保存在当前连接内存中 |
| 构建目标 | 远程控制、BLE 事件上传和归档维护页面不进入 Xcode Target |
| 自动验证 | 13 项测试、无签名构建、签名构建和签名校验通过 |
| 真机安装 | 已安装到配对 iPhone，并从设备读回 `1.0 (24)`；未启动 App，未发送 BLE 指令 |

## 协议范围

活跃命令白名单严格限制为：

`0x01`、`0x05`、`0x10`、`0x15`、`0x31`、`0x51`、`0x52`、`0x60`、`0x61`、`0x62`、`0x81`。

归档代码中的 `0x85`、`0x91`、`0xFA`、`0xFB`、`0xFC`、`0xFF` 等扩展命令未纳入。完整映射见 [BLE V1.2.5 功能清单](documentation/protocol-v1.2.5.md)。

## 已有实车证据

- Build 21 和 Build 22 能完成设备认证，但新增写入门禁导致主锁按钮不产生车辆动作。
- Build 23 删除该回调顺序依赖，恢复直接写入、协议回执和锁态回读。用户已确认开锁与关锁测试通过。
- Build 23 每次操作后主动断开的问题已定位为 App 自加的保守策略，不是厂商协议要求。旧工具和文档都支持当前连接内持续复用连接 Key。

## 尚未完成

Build 24 仍需要以下人工验收：

1. 连接后的 `0x31` 与 `0x60` 数据正确，重复刷新不掉线。
2. 同一 BLE 连接内连续开锁和关锁，仪表、动力、轮毂锁与 App 回读一致，仪表不重启。
3. `0x51` 旧骑行数据读取正确，保存后再决定是否测试 `0x52` 清除。
4. `0x61` 每项基础设置逐个生效，未选择项保持不变。
5. `0x62` 高级设置逐项生效，掉电保存行为符合选择。
6. `0x81` 三类外部锁先查询，再在隔离条件下分别验证解锁和上锁。

代码、测试、编译和安装都不能代替上述物理验收。新增写功能未经验收前，不应一次修改多个变量。
