# 历史 iPhone App 页面与交互流程

> 本文记录 Build 20 及更早的多页远程方案，仅用于历史审计。Build 22 当前流程以 `documentation/flows.md` 为准，远程、地图、记录、维护、Face ID 和自动状态读取均未进入当前 App。

## 1. 产品定位

App 是一台电助力山地车的个人现场与远程调试工具。现有 BLE 功能必须继续在无网络时完整工作；新增远程功能只通过自建单车网关读取状态和发送受控命令。两个通道明确分开，控制指令不自动降级或补发。BLE 结果事件的离线同步只上报已经发生的事实，不属于控制指令补发。

首版使用免费 Personal Team 真机安装。App 在前台时可以展示即时告警，后台、锁屏或被系统终止时不承诺通知。服务端保存活动告警，App 下次启动时置顶展示。

本文记录已确认的 App 需求。协议能力仍须通过模拟器和实车分阶段验收。

## 2. App 内部结构

保留现有 `BLEDeviceManager` 和协议实现，新增：

- `RemoteAPIClient`：HTTPS 请求、签名、错误映射和条件缓存。
- `RemoteStore`：云端车辆、位置、轨迹、告警和命令状态。
- `AppAuthManager`：首次配对、Secure Enclave 密钥和 Face ID 控制签名。
- `ConnectivityStore`：区分手机网络、云端 API、IoT 在线和 BLE 连接。
- `CapabilityCatalog`：渲染指令中心，不包含任意原始指令发送能力。
- `PendingBLEEventStore`：本地保存尚未同步的 BLE 开关锁事件，按 UUID 幂等补报。

BLE 状态与远程状态不合并成一个布尔值。界面始终显示信息来源和采集时间。

## 3. 导航结构

底部使用四个页面：

1. **车辆**：聚合状态、告警、开关锁和找车。
2. **地图**：最后位置、立即定位和当前骑行轨迹。
3. **记录**：远程指令、7 天或 30 天骑行与告警记录。
4. **更多**：云端配对、完整指令目录、BLE 密钥、维护、保留策略和日志。

现有“信息”“控制”“维护”“安全”内容迁入“更多”的二级分组，避免同时保留两套重复入口。Build 14 已完成四页骨架、车辆首页、D0 地图、指令与告警记录、骑行分段、历史详情、保留设置和离线移动推断。

## 4. 状态展示规范

首页分别显示：

| 状态 | 示例 | 数据来源 |
| --- | --- | --- |
| 手机网络 | 可用、不可用 | iOS 网络路径 |
| 云端 API | 可达、不可达 | HTTPS 请求 |
| IoT 设备 | 在线、静默、离线 | 服务端有效帧与静默阈值 |
| BLE | 已连接、扫描中、未连接 | CoreBluetooth |
| 车辆锁车状态 | 已解锁、已锁车、逻辑关锁、未知 | 主锁回包、状态上报和实车联动结果 |
| 外部锁兼容性 | 因果未确认、危险诊断禁用 | `L5` 或 BLE `0x81` 诊断，不作为本车锁车状态 |
| 安全状态 | 已撤防、等待布防、已布防、告警中 | 服务端状态机 |
| 定位策略 | 60、300、3600 秒、未确认 | D1 期望值与确认值 |

状态不能只依赖颜色。图标旁必须有文字；数据过期时显示“最后更新于”和数据年龄。D1 期望值与确认值不一致时显示“策略等待设备确认”，不能显示为已经生效。

IoT 超过 420 秒没有有效报文时显示“通信静默”，超过 720 秒显示“IoT 离线”。IoT 离线不等于手机或云端 API 不可用。

## 5. 首次启动与配对

### 5.1 本地 BLE

沿用现有流程：用户在设置中输入 8 字节设备密钥，密钥只进入 iOS Keychain。扫描、连接、认证和状态读取保持不变。未保存密钥时禁用 BLE 连接按钮。

### 5.2 云端配对

1. 用户在服务器终端生成一次性配对码。
2. App 打开“设置 > 云端连接”，输入 API 域名和配对码。
3. App 验证 HTTPS，生成只读密钥和 Face ID 控制密钥。
4. 配对成功后清空输入框，不保存配对码。
5. App 拉取 `/vehicle`、`/settings` 和 `/capabilities`。

配对失败不影响 BLE。删除云端配对只删除手机本地凭据，服务端公钥仍需通过管理命令撤销，避免误删后历史审计失去归属。

## 6. 启动与刷新流程

App 启动后立即显示上次缓存，并标明“缓存”。随后并行执行：

1. 检查手机网络和云端 API。
2. 拉取车辆聚合状态。
3. 拉取活动告警。
4. 如告警存在，首页顶部显示不可忽略的告警卡片。
5. App 在车辆首页前台时每 15 秒只刷新车辆、能力、命令和活动告警。位置历史、单次轨迹、审计、设备会话和设置只在启动、手动刷新或进入对应页面时按需读取。

切到后台时停止轮询。重新进入前台立即刷新。不得依赖后台 WebSocket，也不得把网络失败误报为 IoT 离线。

服务端把位置历史、单次轨迹、审计和设备会话定义为敏感明细读取。认证客户端成功读取后必须记录操作者、对象、查询上限和时间，但不得把读取令牌、签名、原始定位帧、原始网络地址或设备数据正文写入审计。审计读取本身在下一次查询中可见。常规 15 秒运行态轮询不读取这些明细，避免审计日志持续膨胀。

## 7. 首页操作

### 7.1 通道选择

每个可双通道执行的动作明确标注“云端”或“附近 BLE”：

- BLE 已连接时，近场卡片显示 BLE 开锁、BLE 关锁和信号强度。
- IoT 在线时，云端卡片显示远程开锁、远程关锁、立即定位和声音找车。
- App 不根据连接质量自动换通道，也不在一个通道超时后尝试另一个通道。

### 7.2 开锁

```text
点击远程开锁
  -> 展示当前锁状态与通道
  -> 长按 1.2 秒
  -> Face ID
  -> 创建带 Idempotency-Key 的命令
  -> 展示命令时间线
  -> 成功、明确失败、结果未知或无需操作
```

成功后首页切换为已开锁、已撤防、60 秒定位，并创建当前骑行。若有活动异常移动告警，授权开锁自动解除。`unknown` 状态只提供“刷新状态”，不提供一键重试。BLE 开锁也要求长按和 Face ID。

2026 年 8 月 21 日实车已确认 BLE 主开锁 `0x05` 会同时点亮仪表、恢复车辆动力并打开轮毂锁。App 收到成功回包后仍应展示一次车辆侧结果确认；测试版本允许用户确认，后续获得可信电子状态源后再自动完成。

同日实车也确认远程 TCP `R0 → L0 → 确认` 链路会完成相同的一体化开锁。远程命令必须保留 R0 与 L0 字段校验、单车并发限制和操作时间线，不允许把 L0 作为无状态的裸指令直接发送。

### 7.3 关锁

远程关锁先展示醒目的轮毂锁安全说明。用户确认车辆完全停稳且无人骑行后，长按 1.2 秒并通过 Face ID。App 在签名请求中提交人工停稳确认，服务端校验该参数后进入 R0、L1 流程。

请求被阻止时显示具体原因：

- 缺少签名的人工停稳确认。
- 设备离线或连接中断。

人工确认不是自动静止检测，也不能用于自动流程。真实关锁必须表现为仪表熄灭、车辆动力断开、轮毂不能转动，IoT 保持供电。只有这一联动结果得到可信确认后，才显示 5 分钟布防倒计时和准确结束时间。仅有 L1、BLE 或 H0 逻辑关锁结果时显示“逻辑关锁，等待现场确认”，不启动自动布防。BLE 关锁同样要求长按和 Face ID，成功后只同步已经发生的 BLE 事件，不重复发送云端关锁。

2026 年 8 月 21 日实车已确认 BLE 主关锁 `0x15` 会同时熄灭仪表、断开车辆动力并闭合轮毂锁。App 收到成功回包后仍应展示一次车辆侧结果确认；测试版本允许用户确认，后续获得可信电子状态源后再自动完成。

同日后续实车确认远程 TCP `R0 → L1 → 确认` 链路也会完成相同的一体化关锁。远程 L1 回包中的用户和骑行时间戳应与活动 L0 开锁记录关联；除结果码外，服务端还应在正式实现中核对活动骑行上下文，不能只依赖单个成功字段。

如果逻辑状态显示关锁，但仪表仍亮或轮毂仍可转，App 不得显示“无需操作”。它应进入受保护的“锁车状态不一致”流程，先重新读取状态并要求用户现场确认三个联动结果。由于超时命令可能在蓝牙断开后延迟执行，该流程不得自动再次发送主锁指令。只有用户确认车辆仍未锁定并重新长按授权后，才允许创建一次新的操作。

解锁状态默认撤防。App 另设“手动布防”，用于车辆失窃等特殊情况。手动布防必须明确显示机械锁仍可能处于解锁状态，不能把安全状态和机械锁状态合并展示。

### 7.4 找车

“声音找车”发送 `V0,2`，按钮进入 10 秒冷却。2026 年 8 月 21 日已完成实车声音验收，设备成功回包且车辆实际发声。BLE 信号找车作为独立工具，只显示 RSSI 强弱，不声称距离值准确。

### 7.5 BLE 事件同步

BLE 开关锁获得成功回包且锁状态回读一致时，App 先把事件 UUID、动作、设备时间、BLE 结果和当前回读状态写入本地，再调用 `POST /api/v1/ble-events`。不可用时保留在本地队列。

- 事件补报成功后才从本地队列删除。
- 同一事件重复上传使用相同 UUID，不生成第二次业务动作。
- 事件在 24 小时内可以同步锁、安全、骑行和定位策略目标；只有 IoT 在线时才创建 D1 请求。
- 超过 24 小时仍可上传审计，但不再改变当前状态。
- IoT 离线时，服务端接收 BLE 事件，但所有 D1 和其他设备下行请求直接拒绝。
- 补报永远不能转换成新的开锁或关锁命令。

## 8. 地图与轨迹

地图页包含：

- 最后有效位置、采集时间、数据年龄、卫星数和 HDOP。
- “立即定位”按钮及 30 秒结果等待。
- 当前安全状态和 D1 策略。
- 当前骑行轨迹或用户选中的历史轨迹。

定位结果处理：

- 收到有效点时移动车辆标记并显示精度信息。
- 收到无效点时提示“本次定位无效”，保留旧标记。
- 30 秒无回包时命令为结果未知，不删除旧位置。
- 被漂移规则过滤的点不参与连线，详情中仍可标记为已过滤。
- 长时间没有点时轨迹使用断线，不跨缺口画直线。
- 首版不采集手机 GPS。IoT 无蜂窝网络时显示轨迹缺口，不使用手机位置冒充车辆 IoT 位置。

App 仅在用户需要显示本人位置、到车距离或导航时请求“使用 App 时”定位权限。查看车辆位置本身不需要手机定位权限。

## 9. 告警流程

### 9.1 布防

关锁成功后首页出现 5 分钟倒计时。倒计时结束并从服务端确认后显示“已布防”。等待期内收到的移动事件只进入事件详情，不弹告警卡片。

### 9.2 异常移动

App 前台发现活动告警时：

- 触发声音、触感和醒目的顶部告警卡片。
- 展示首次和最近触发时间、触发次数、最后位置及定位年龄。
- 地图显示告警期间位置点，并标注定位间隔目标为 300 秒。
- 提供“确认并解除告警”和“声音找车”。

非法移动和非法拆除使用声音、振动和高优先级红色卡片；倒地播放一次声音并显示普通告警；低电量只显示提醒。声音遵循用户设备静音与系统规则，不尝试绕过系统音量。同类告警 60 秒内合并；超过 60 秒再次触发时再提示一次，不持续循环播放。

Build 14 在 IoT 重连后发现关锁期间位置明显变化时显示“疑似离线期间移动”。卡片标注为服务端根据两次重连定位推断，并展示断网前停车位置时间和重连定位时间，不显示成实时 W0。默认 200 米位移阈值与 75 米样本一致性阈值仍待户外校准。

### 9.3 解除

“确认并解除告警”需要 Face ID。完成后：

- 车辆仍关锁：安全状态回到已布防，D1 目标恢复 3600 秒。
- 车辆已开锁：安全状态回到已撤防，D1 目标恢复 60 秒。

如果 D1 回包超时，告警可显示为已确认，但同时展示“定位间隔恢复未确认”。两个结果不能混为一个成功状态。

IoT 离线时仍可确认并解除 App 内告警，但 D1 请求立即拒绝、不排队。设备以后重新上线并上报新的 H0 后，服务端才根据当时状态创建新的 D1 请求。

## 10. 历史页面

### 10.1 骑行历史

按日期倒序显示起止时间、持续时间、估算距离、有效点数和数据完整性。点击进入地图轨迹。活动骑行置顶，并显示仍在采集。

60 秒定位只能提供路线级轨迹，页面不展示瞬时运动成绩。距离为过滤后的 GPS 估算值，必须标注“估算”。

### 10.2 告警历史

按活动、已确认、已解除分类，展示告警类型、触发次数和关联位置。被 5 分钟等待期抑制的事件放在“诊断事件”，不显示成用户告警。

### 10.3 保留设置

“更多 > 数据保留”提供“7 天”和“30 天”单选：

- 7 改 30：立即保存，并说明过去已删除的数据不能恢复。
- 30 改 7：弹出二次确认，说明下一次清理会删除超过 7 天的轨迹。
- 修改失败：保留服务端当前值，不提前改变界面选择。

## 11. 指令中心

指令中心由服务端 `/capabilities` 和本地 BLE 目录共同生成。每个指令显示：

- 中文名称、协议编号和通道。
- 用途、参数说明和掉电保存属性。
- 风险等级和是否需要 Face ID。
- 支持状态：实车已验证、协议明确未验证、只读上报、内部流程、危险维护、不适用。
- 最近一次执行时间、结果和安全回包摘要。

展示分组：

1. 日常控制：开锁、关锁、立即定位、声音找车。
2. 状态诊断：Q0、H0、S6、G0、E0、I0、M0、Z0、锁状态查询。
3. 车辆设置：S5、D1、S7、S4 和对应 BLE 设置。
4. 外部锁兼容性诊断：L5、BLE `0x81`，实测无回包且存在无法归因的延迟关锁风险。在隔离变量验证完成前固定标记为“危险维护”，目录和维护页均禁止执行，不能降级成“不适用”。
5. 事件：W0、S1。
6. 密钥与升级：K0、U0、U1、U2、BLE OTA。
7. 内部协议：R0、认证、应答和错误帧。
8. 归档扩展：RFID、电源、日志、系统信息传输等。

“展示全部指令”不等于“全部提供执行按钮”。只读上报和内部流程只展示解释；危险维护默认折叠；协议未确认功能禁用，并明确缺少哪一层证据。App 不提供原始 TCP 或 BLE 数据输入框。

Build 16 已按上述边界实现目录页。服务端清单是代码内静态审核数据，App 只把它转换为展示项，不根据服务端名称、协议号或参数文本动态生成动作。BLE 的 11 个协议编号由 App 内置清单补齐。Build 17 进一步把实际收到的 BLE 认证、主锁、状态、骑行、设置、外部锁和旧数据回包，以及 RFID、电源、日志、配置和 OTA 结果写入同一最近结果模型。目录展示通道、用途、参数、持久化、风险、支持标签、禁用原因、最后结果和安全回包摘要，真实操作仍只存在于车辆首页或既有近场维护页面。旧骑行正文、设备日志正文、系统配置和认证连接 KEY 不进入指令中心。

所有会改变车辆状态的超时结果统一显示为“结果未知，可能延迟执行”。App 随后只允许读取状态和展示现场检查提示，不提供自动重试。若车辆稍后完成动作，时间线追加“延迟完成”，保留原命令 ID，不创建第二条控制命令。

## 12. 更多与维护

更多页面分为：

- 云端连接：API 地址、配对状态、客户端撤销提示。
- BLE 安全：设备密钥和维护密钥，继续保存在 Keychain。
- 数据：轨迹保留 7 或 30 天、脱敏日志导出。
- 审计与会话：统一审计、当前与历史 IoT 会话、收发和解析计数、Q0/H0 时间与地址摘要。
- 服务设置：轨迹保留 7 或 30 天可修改，其余部署阈值只读。
- 设备维护：服务器、APN、OTA 和诊断日志，默认只允许近场 BLE。
- 关于：App 版本、协议版本、能力验证说明。

设备密钥永不回显。直接车轮锁控制、设备密钥修改、服务器、APN、OTA、设备电源和清除设备数据都要求 Face ID 与二次确认。上述维护功能首版只允许近场 BLE，云端指令中心只展示禁用原因。服务器地址和 APN 修改成功后，不自动执行重连以外的其他控制。

## 13. 失败与幂等文案

| 场景 | 用户文案 | 后续操作 |
| --- | --- | --- |
| 已在目标状态 | 无需操作，车辆已经开锁或关锁 | 关闭结果页 |
| 手机无网络 | 手机当前无法访问云端 | 使用 BLE 或稍后刷新 |
| API 不可达 | 云端服务暂时不可达 | 刷新，不排队 |
| IoT 离线 | 设备离线，命令未发送 | 查看最后通信时间 |
| 命令冲突 | 车辆正在执行另一项操作 | 查看现有命令 |
| 明确失败 | 设备返回失败 | 查看诊断，不自动重试 |
| 结果未知 | 已发送，但未确认最终结果 | 刷新状态，不自动重试 |
| D1 未确认 | 定位策略已申请，设备尚未确认 | 显示期望值与确认值 |
| IoT 离线时修改 D1、S5 或 H0 间隔 | 设备离线，请求已拒绝且不会补发 | 等设备上线后重新操作 |
| 缺少停稳确认 | 请先确认车辆完全停稳且无人骑行 | 重新长按并通过 Face ID |

相同 `Idempotency-Key` 的重复响应绑定同一命令。按钮在请求提交后立即锁定，直到获得终态或超时，不因页面切换重新发送。

## 14. 隐私、日志与无障碍

- App 缓存只保存必要的车辆状态和近期地图数据，受 iOS 数据保护机制保护。
- 导出日志默认脱敏 IMEI、BLE MAC、公网地址、签名、密钥和精确位置。用户主动导出轨迹时单独提示包含位置隐私。
- 告警声音同时配合触感和文字，不能只依赖声音或颜色。
- 支持 Dynamic Type、VoiceOver 标签和减少动态效果。
- App 截图或系统切后台预览时，对密钥输入和精确位置使用隐私遮罩。

## 15. 首版验收清单

1. 无网络时现有 BLE 扫描、认证、读取和控制不受影响。
2. 四种连接状态互不混淆，所有缓存数据都有时间标记。
3. 开锁、关锁、找车和定位重复点击均不重复下发。
4. 远程关锁缺少签名停稳确认时必定被阻止，成功回包后仍提示现场核对物理结果。
5. 关锁后准确显示 5 分钟倒计时，重启 App 后倒计时来自服务端。
6. 前台活动告警只响一次，重新打开 App 能看到未解除告警。
7. D1 期望值与确认值不一致时明确显示未确认。
8. 轨迹能显示缺口、无效点和被过滤点，不制造虚假连续路线。
9. 7 天与 30 天设置和二次确认符合服务端实际值。
10. 指令中心覆盖协议目录，未验证能力不显示为可用。
11. BLE 开关锁事件可以在线上传、离线暂存、24 小时补报和按 UUID 去重。
12. IoT 离线时所有设备请求直接拒绝，重连后不重放旧请求。
13. 重连定位变化告警始终标记为推断，首版不采集手机辅助轨迹。
