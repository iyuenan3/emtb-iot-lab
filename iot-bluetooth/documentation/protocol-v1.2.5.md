# BLE V1.2.5 实现范围

Build 33 的线协议根据《欧米滑板车 IoT 设备接口协议（内置 IoT 版）V1.2.5 云途》蓝牙章节重新实现。没有复用旧 App 协议代码。

## 当前命令

| 命令 | 用途 | 是否用户功能 |
| --- | --- | --- |
| `0x01` | 用 8 字节设备密钥认证并取得本连接 Key | 内部步骤 |
| `0x31` | 读取锁信息，建立与已验证 Mac 流程一致的会话 | 内部只读步骤 |
| `0x60` | 读取车辆信息，完成会话初始化 | 内部只读步骤 |
| `0x05` | 开锁控制与同命令 `0x02` 必要回执 | 是 |
| `0x15` | 关锁控制与同命令 `0x02` 必要回执 | 是 |
| `0x10` | 设备返回的协议错误 | 只接收 |

其他 V1.2.5 命令没有代码模型、生产发送入口或界面入口。

## 帧规则

- 帧头固定为 `A3 A4`。
- RAND 在线路中存储为明文随机数加 `0x32`。
- KEY、CMD 和 DATA 与明文 RAND 异或。
- CRC8 对加密后的 CRC 前字节计算，多项式实现为 `0x8C`。
- 多字节用户 ID 和时间戳按大端写入。
- `0x05` 控制载荷为控制标志、用户 ID、时间戳和正常开锁状态。
- `0x15` 控制载荷为 `[0x01]`。
- 收到控制结果后发送相同命令、载荷 `[0x02]` 的必要回执。

测试使用文档附录中的 `OmniW4GX` 和 RAND `0x1E` 认证向量验证整帧字节与 CRC8。该公开示例只用于测试，不是当前车辆密钥。

## 物理边界

MacBook 标准开锁和关锁流程已有实车通过记录。Build 33 已完成 iPhone 单次开锁和单次关锁验收，仪表、晃动报警和自动断开均符合预期。协议成功码仍不能替代每次操作的现场物理确认。
