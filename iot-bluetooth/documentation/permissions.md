# 权限与安全

## iPhone 权限

| 权限或能力 | 用途 | 触发时机 |
| --- | --- | --- |
| Bluetooth | 扫描和控制指定 IoT | 用户选择附近蓝牙并连接时 |
| Face ID 或设备密码 | 授权远程控制和 BLE 高风险写操作 | 每次高风险操作前 |
| 网络 | 访问 HTTPS 远程服务 | 已配对后的读取或远程操作 |
| 文件选择 | 选择本地 OTA 固件 | 用户进入维护并主动选择时 |
| 分享 | 导出脱敏现场日志 | 用户主动导出时 |

当前 App 不申请手机定位权限。车辆位置只来自 IoT，查看车辆位置不需要读取 iPhone GPS。精确车辆位置只能通过已配对客户端的读取令牌访问。

## 凭据存储

- 8 字节设备密钥和 4 字节维护密钥保存在 iOS Keychain，不回显、不写日志。
- 远程控制私钥在 Secure Enclave 生成，服务端只保存公钥。
- 一次性配对码不持久化，读取令牌和客户端编号保存到 Keychain。
- Mac 的 `.env.local` 只供命令行 BLE 调试，不进入 iPhone App。

## 操作保护

- 开锁和关锁必须长按 1.2 秒。
- 远程与 BLE 开关锁都要求设备所有者认证。BLE 的原始写方法为私有，页面只能调用经过 `deviceOwnerAuthentication` 的公开入口。
- 服务器、APN、OTA 和清除旧数据位于“更多”的二级页面，并保留二次确认。外部锁虽然在二级页面展示，但因实测无回包和延迟执行风险固定禁用；未来完成隔离验证后若开放，仍必须增加 Face ID 和二次确认。
- 超时结果显示“结果未知”，只允许刷新，不自动重试。
- BLE 锁状态观察写回需要已配对客户端和 P-256 签名，不要求 Face ID，因为它只同步已发生的只读回读，不控制车辆。
- BLE 操作事件补报同样要求 P-256 签名和相同的事件 UUID、幂等键。补报只同步已经成功并回读一致的事实，不生成新的开关锁指令，因此上传阶段不再要求 Face ID。

## 日志与快照脱敏

- 分享日志会遮罩 IMEI、MAC、服务器地址、IP、密钥和位置等敏感内容。
- 本地设备快照不保存可直接识别设备或基础设施的原值，并启用 iOS 文件保护。
- 精确位置仍只在已配对客户端的功能页面展示，不写入可分享日志。

## 已知缺口

Build 12 的告警只在 App 前台使用系统声音与触感，不申请后台通知权限。自动静止判断和机械锁电子确认尚未实现，仍依赖现场确认。
